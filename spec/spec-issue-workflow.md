# GitHub Issue Clarification Workflow

- `.github/workflows/issue-clarify.yml` runs `anthropics/claude-code-action@v1` (authenticated via the `CLAUDE_CODE_OAUTH_TOKEN` repo secret, tied to a Claude Pro/Max subscription) on issue opened/edited and issue comment created/edited events. It replaced an earlier hand-rolled script that called the free GitHub Models inference API, which GitHub permanently retired on 2026-07-30.
- Answers can be given either by **editing the issue description** or by **replying in a comment**. Editing the description updates the existing tracking comment in place (`track_progress: true` reuses one tracking comment per issue for `issues: opened/edited` events). Replying in a comment cannot edit anything in place — GitHub's MCP tooling has no tool to edit an arbitrary existing comment — so each comment-triggered reply posts a fresh comment with the up-to-date question state instead. This is a known tool limitation, not a bug.
- The action reads `CLAUDE.md` and the `spec/*.md` files itself; the issue body and full comment thread are already provided in context (Bash/`gh` access is not needed or granted).
- When a tracking comment is available to update, the workflow sets it to "🤔 Thinking…" as its first action so there's a visible in-progress indicator, then replaces it with the real content once done.
- While questions remain open, the current message re-annotates the same numbered question list on each pass (same numbering/order/wording) with traffic-light status emojis (`🟢` answered, `🟡` partial, `🔴` unanswered) plus short answer-understanding blockquotes for answered/partial items; new follow-up questions are only appended, continuing the numbering, and only when genuinely needed.
- Once every question is 🟢, the workflow uses the `update_issue` tool to rewrite the issue body itself (keeping the same template structure/headings already used — bug report vs feature request — filled in with the clarified answers), then posts/updates a short confirmation instead of repeating the question list.
- That confirmation also includes a **Suggested spec update**: a hand-drafted unified diff (in a `diff` code block) against whichever `spec/*.md` file(s) this change would touch, per the spec-sync convention in `CLAUDE.md`. This is a preview only — no file on disk is actually edited, no branch or commit is created. If no spec change would be needed, the workflow says so explicitly instead of a diff.
- The job guards against re-triggering on its own comments/edits by skipping events where `sender.login` is `claude[bot]`. There is no downstream agent that automatically implements the issue — clarification is the full extent of this workflow.
