# GitHub Issue Clarification Workflow

- `.github/workflows/issue-clarify.yml` runs `anthropics/claude-code-action@v1` (authenticated via the `CLAUDE_CODE_OAUTH_TOKEN` repo secret, tied to a Claude Pro/Max subscription) on issue opened/edited events. It replaced an earlier hand-rolled script that called the free GitHub Models inference API, which GitHub permanently retired on 2026-07-30.
- Answers are given by **editing the issue description**, not by commenting — GitHub's MCP tooling has no way to edit an arbitrary existing comment (only the action's own tracking comment), so `issue_comment` is not a trigger for this workflow.
- The action reads `CLAUDE.md` and the `spec/*.md` files itself; the issue body and its own prior tracking comment are already provided in context (Bash/`gh` access is not needed or granted). `track_progress: true` makes the action create and reuse a single tracking comment per issue.
- While questions remain open, the tracking comment re-annotates the same numbered question list on each edit (same numbering/order/wording) with traffic-light status emojis (`🟢` answered, `🟡` partial, `🔴` unanswered) plus short answer-understanding blockquotes for answered/partial items; new follow-up questions are only appended, continuing the numbering, and only when genuinely needed.
- Once every question is 🟢, the workflow uses the `update_issue` tool to rewrite the issue body itself (keeping the same template structure/headings already used — bug report vs feature request — filled in with the clarified answers), then replaces the tracking comment with a short confirmation instead of repeating the question list.
- The job guards against re-triggering on its own edits by skipping events where `sender.login` is `claude[bot]` (its own `update_issue` call would otherwise re-fire `issues: edited`). There is no downstream agent that automatically implements the issue — clarification is the full extent of this workflow.
