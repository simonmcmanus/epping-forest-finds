Why nothing was applied this run

The changeset below is ready. It was not committed because the safety-gate test run failed on something unrelated.

What happened, in order:

  1. Branch created: weekly-data-report/2026-09-03, from the tip of main.
  2. Changeset applied cleanly: scripts/apply_weekly_changeset.py added Forest Kitchen and removed the Loughton Zizzi (by OSM id, so the South Woodford branch was untouched), with nothing skipped.
  3. Unit suite run as the required safety gate: node --test test/forest-finds.test.js failed, deterministically, across three separate runs. The failure is an assertion at test/forest-finds.test.js:3146 - once the graph is ready, the route should follow the path via its middle vertex instead of going straight - inside a routing/pathfinding test that builds its own synthetic in-memory road graph and never reads any dataset file. git diff --stat against main confirmed the only file this run had touched was data/local-landmarks-food.geojson, so this failure predates this run and is unrelated to the proposed changes; it looks like a pre-existing bug in the routing/pathfinding code worth a look separately from this data report.
  4. Playwright end-to-end suite: started for a complete picture, but did not finish within this run session and was stopped before producing a result. Not a pass; genuinely not run to completion.
  5. Per the workflow safety rule - this run push does not retrigger the repository CI, so this test run is the only gate - the applied changes were reverted with git checkout -- data/local-landmarks-food.geojson before anything was committed. The dataset file in this pull request is therefore byte-identical to main.

Methodology and limitations

Read this before acting on anything above.

  1. The FSA cross-check worked this run. The Food Hygiene Rating Scheme API at api.ratings.food.gov.uk answered every request with the x-api-version: 2 header and no key needed. It was used to verify Forest Kitchen as a genuine, currently-rated establishment; to confirm Zizzi has no active FSA registration anywhere in Loughton or at IG10 1LA; to confirm the Loughton Morrisons supermarket (not a separate cafe) is what is FSA-registered at that address; and to confirm Piya, at 74-76 High Street Epping, matches an FSA listing and is already correctly in the dataset. It returned nothing for The Aviary Bar and Brasserie in Loughton, which is inconclusive rather than a negative signal, since newly opened businesses can take months to receive their first inspection.
  2. Coverage gap on small independent turnover. General news search surfaces closures and openings that got press or directory coverage - mostly chains, or independents with a strong online presence. Chingford, Chigwell, Theydon Bois and Waltham Abbey turned up nothing this run; that almost certainly reflects search coverage rather than an accurate absence of any change in four settlements out of eight.
  3. Search results can be years stale and need a second check. Two leads from this run turned out to be wrong on first read: a Caterer article about La Sala Woodford Green opening is from 2014, not this week, and the venue closed years ago; and the top search snippet for Bakers Lane roadworks describes an older advance notice, not the current phase shown on the live Essex Highways project page. Both are corrected above rather than repeated at face value.
  4. Two Council pages could not be read this run. Both eppingforestdc.gov.uk pages checked (advance road closures, and the forest events page) returned an interactive Cloudflare verification challenge to both the fetch tool and a direct curl request with a standard browser user agent, rather than page content. The City of London Corporation forest news page, by contrast, fetched cleanly by the same method.
  5. Nothing was fabricated. Every finding above cites at least one source actually fetched or searched this run. Candidates that could not be pinned down with confidence - The Aviary Bar and Brasserie address, and the exact Zizzi closure date - are reported as open questions rather than guessed.
